## 1. 文档库目标

本目录 `docs/sourceReader` 用于沉淀一份可重新实现 `qwen-code` 的 Markdown 文档库。读者应能：

- 先看懂系统骨架：有哪些进程、模块、职责、依赖、数据入口与出口。
- 再跟读一个真实最小例子：从 CLI 输入到模型响应或工具执行返回。
- 再按调用顺序逐步拆解主链路：谁调用谁、参数如何传、返回值如何消费、错误如何传播。
- 最后补齐源码中的全部逻辑与技术点：模块、接口、配置、数据流、并发、失败恢复、测试与部署。

语言为中文，技术术语保留英文，例如 `CONNECT`、`TLS`、`Pipe`、`goroutine`、`stream`、`tool call`、`session`、`daemon`。

## 2. 四层推进顺序

必须按以下顺序编写，不可跳级：

1. **第一层：简单框架**
   - 只讲系统骨架、边界和主路径。
   - 不展开每个函数、每个分支。
   - 读者读完应能回答：项目是干什么的、运行时有几块、请求大概怎么走。

2. **第二层：简单例子走完全路径**
   - 选一个真实、最小、可跟读的例子。
   - 覆盖全路径：客户端/CLI → 核心服务 → 模型/工具/外部源 → 响应回到界面。
   - 写清真实文件路径、函数名、关键参数、返回值和副作用。
   - 只走主成功路径，失败、重试、边界条件点到为止。

3. **第三层：详细逐步说明**
   - 在全路径例子走通后，按调用顺序逐步拆开每一跳。
   - 每跳写清：谁调用谁、参数如何传递、返回值如何消费、错误如何传播、状态如何变化。
   - 用 Mermaid 时序图/流程图对照真实符号。

4. **第四层：补齐源码中所有逻辑与技术点**
   - 补齐其余入口、模块、分支、配置、数据模型、并发、失败恢复、测试与部署。
   - 覆盖约定范围内的全部源码逻辑与技术点。
   - 不得用“同上”“略”“以此类推”代替未展开的模块。

## 4. 单篇文档骨架

每篇正文按以下结构：

```markdown
[上一篇：标题](prev.md) · [总目录](README.md) · [下一篇：标题](next.md)

# <场景化标题>

> **场景**：一句话说明跑通了什么（命令 / 客户端 / 目标）。
> **时间**：采样时间（CST）。
> **工具版本**：curl x.x, qwen x.x（含依赖版本）。

> **阅读说明**：源码片段主要对应当前工作区源码；若本地已有后续修改以当前源码为准。本文讲调用关系与数据流，不把行号当稳定 API。

---

### 本文件内容

1. [xxx](#1-xxx)
2. [yyy](#2-yyy)

其余阶段见[总目录](README.md)。

---

## 1. xxx

（正文：ASCII 图 / 表格 / 代码 / 源码引用）

---

[上一篇：...](prev.md) · [总目录](README.md) · [下一篇：...](next.md)
```

要点：

- 顶部与底部都有导航行。
- 标题下先放 `> 场景` 与 `> 阅读说明` 两个 blockquote。
- `## 本文件内容` 用带锚点的有序列表做本篇目录。
- 章节 `## N. 步骤/主题`、`### N.M 子主题`，序号与“步骤一/二”对齐。

## 5. 图表约定

- **端到端协议/网络流**：用 ASCII 框线图，例如 `┌─┐│▶◄═`，多列标出参与方，每步标 `Step N:` 与方向箭头。
- **代码/调用关系/架构**：用 Mermaid `flowchart TD/LR`，节点用方括号 `"文本"` 或 `[file.go]`。
- **运行态/状态机**：也用 Mermaid `flowchart` + 菱形判断节点。
- 两种图分工：ASCII 给人看流程，Mermaid 给工具看代码关系，不要混用。

---

## 6. 源码引用规则

- 标注格式：`文件: packages/core/src/core/client.ts, 第 2313-2600 行`。
- 依赖库代码钉版本，例如 `github.com/go-gost/x v0.15.1`。
- 引用真实日志时保留 `caller:"parsing/tls.go:125"` 字段，建立“日志行 ↔ 源码位置”对应表。
- 代码片段用 `go`、`bash`、`json` 等围栏；关键行加 `★` 标记、`═══` 分隔注释、行内 `// ← 说明`。
- 必须声明：行号随版本变化，当前源码为权威。
- 把“日志输出 ↔ 内部调用链 ↔ 说明”做成三列表。

---

## 7. 常用表格类型

- **环境/组件表**：组件 / 值（IP、端口、协议、版本）。
- **调用链表**：序号 / 动作 / 内部调用链(file:line) / 说明。
- **日志对应表**：调度阶段 / 调用时机 / 关键动作 / 日志输出。
- **源码改造清单表**：优先级(P0/P1/P2) / 文件 / 需添加或修改。
- **策略对比表**：策略 / 内容完整性 / 对业务影响 / 适用。

## 8. README 总索引约定

- 按主题把单篇分组，每组给一句定位。
- 每组一个有序表格：顺序 / 文档(链接) / 内容(一句话)。
- 末尾放推荐阅读路径的 Mermaid `flowchart TD`。
- 顶部注明基础命令与版本钉死说明。
